# LLM Chatbot Evaluation & Safety Testing Framework

A retrieval-augmented (RAG) Q&A chatbot over home-appliance manuals, served through a
FastAPI REST API, plus a test framework that scores every answer for groundedness, flags
hallucinations, attacks the bot with prompt-injection and jailbreak prompts, checks
for personal-data leaks, and writes a pass/fail + score report for every prompt or model change.

**Stack:** Python 3.12 · LangChain (core + text splitters) · fastembed · FastAPI · Anthropic Claude
(optional) · pytest + requests · Postman/Newman

The full step-by-step explanation is in [`docs/LLM_Chatbot_Eval_Guide.pdf`](docs/LLM_Chatbot_Eval_Guide.pdf).

**Live demo:** <https://appliance-help.onrender.com> (API docs at
[`/docs`](https://appliance-help.onrender.com/docs)). It runs the free offline answerer, so the
first visit after 15 idle minutes takes about a minute to wake up. Manuals uploaded there are
shared with all visitors and wiped on restart, so don't upload anything private.

## Quick start (Windows PowerShell)

```powershell
cd C:\Users\HP\Desktop\llm-chatbot-eval
.\.venv\Scripts\Activate.ps1          # first time: python -m venv .venv; pip install -r requirements.txt
uvicorn app.main:app --reload         # chat page on http://127.0.0.1:8000, Swagger UI at /docs
```

Open <http://127.0.0.1:8000> to use the chatbot: type a question about one of the sample
manuals, or drop your own manual (PDF, Markdown or text) onto the page and ask about it.
The **Guide** link in the menu explains how the project is built and tested.

In a second terminal:

```powershell
.\.venv\Scripts\Activate.ps1
pytest                                # ~486 tests + score report in reports/
python -m evaluation.run_eval --ablation        # scored report, also tests with guardrails OFF
python -m evaluation.run_eval --save-baseline   # make this run the comparison baseline
```

No API key is needed: without one, an offline extractive "mock" answers by quoting the manuals.
To use Claude, copy `.env.example` to `.env` and set `ANTHROPIC_API_KEY`. That also enables
the LLM-as-judge groundedness check.

## Deploying

The [`Dockerfile`](Dockerfile) builds the API and web pages into one container (port 7860, or
`$PORT`), with the embedding and OCR models baked in. It defaults to the offline mock answerer
(`LLM_PROVIDER=mock`), so a public deployment holds no API key.

* **Render (free):** [`render.yaml`](render.yaml) is a Blueprint. In the Render dashboard choose
  **New → Blueprint**, pick this repo and deploy; every push to `main` redeploys.
* **Any Docker host:** `docker build -t appliance-help .` then
  `docker run -p 7860:7860 -e ALLOWED_HOSTS=<your-domain> appliance-help`.
* **Hugging Face Spaces (Docker Spaces need a PRO plan):** `hf auth login`, then
  `python deploy/hf_space.py <username>/<space-name>`.

`ALLOWED_HOSTS` lists the host names the app answers to; requests for any other host are refused.

## Web pages

The API serves the pages itself, so `uvicorn` is all you need:

| URL | Page |
|---|---|
| `/` | **Chat**: ask questions, drop a manual to add it, choose which manuals answer |
| `/guide.html` | **Guide**: how the chatbot is built, evaluated and attacked |
| `/docs` | Swagger UI for the REST API |

Only an explicit list of files is served; the rest of the project (code, `.env`, uploads)
is never reachable from the browser. Each page is a single self-contained file. Edit the
files in `site/src/`, then rebuild:

```powershell
.\.venv\Scripts\python.exe site\build.py
```

## Adding your own manual

Drop a manual on the chat page (or use **Add manual**), in almost any document format:

| Kind | Formats |
|---|---|
| Documents | PDF (including **scanned** PDFs), Word `.docx` / `.doc`, Rich Text, OpenDocument |
| Slides and sheets | PowerPoint `.pptx` / `.ppt`, Excel `.xlsx` / `.xls`, CSV, OpenDocument |
| Web and e-books | web pages, saved web pages (`.mht`), EPUB, XPS |
| Photos and scans | JPEG, PNG, TIFF (multi-page), WebP, BMP, GIF |
| Plain | Markdown, text |

The format is recognised from the file's content, so a wrong extension does not matter.
Scanned pages and photos are read with offline OCR (RapidOCR; about 6 seconds a page, at
most `OCR_MAX_PAGES`=60 per manual); its English model (9 MB) is downloaded once into
`.cache/ocr` and checked against its SHA-256. The chat page shows the progress of a long scan.
The API reads the file, splits it into sections and chunks, embeds them and adds them to the
search index; the chat then answers from that manual only, until you pick "All manuals" again.

| Endpoint | What it does |
|---|---|
| `POST /v1/manuals` | upload a file (multipart field `file`, optional `title` and `upload_id`); 201 new, 200 duplicate |
| `GET /v1/manuals/progress/{upload_id}` | how far a running upload has got, e.g. OCR page 12 of 45 |
| `GET /v1/manuals` | list the sample and uploaded manuals |
| `DELETE /v1/manuals/{manual_id}` | remove an uploaded manual (sample manuals are read-only: 403) |
| `POST /v1/chat` | add `"manual_id"` to answer from one manual only |

Rejected files get a clear message: not a document (a program, audio, video, an archive: 415),
too large (413), damaged, password-protected, or no readable text even with OCR (422).
Uploads are saved in `data/uploads/` with their vectors, and loaded again (without re-embedding)
when the server restarts. Settings: `MAX_UPLOAD_MB` (default 20), `UPLOADS_DIR`,
`OCR_MAX_PAGES` (default 60), `OCR_MODEL_DIR` and `ALLOWED_HOSTS`. Uploads, questions and
deletions sent by other websites are refused, so a page you visit cannot use your local app. When `pytest` or `python -m evaluation.run_eval` start their own server
(the default), they use a temporary uploads folder, so your manuals never change the scores.
Pointed at a running server instead (`API_BASE_URL` / `--base-url`), they see whatever
manuals that server has; the runner warns about uploaded manuals and will not save them into
a baseline.
